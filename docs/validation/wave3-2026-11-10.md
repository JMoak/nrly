`0.3.0-alpha.1`. The [workflow guide](../wave3.md) describes implemented capabilities;
the [implementation plan](../wave3-plan.md) records module boundaries and scope.

The Python suite includes real native Transformer execution, deterministic fixtures,
real subprocess studies, and focused unit tests. It is not 377 pretrained-model
experiments. The new external-model comparator acceptance constructed two distinct
local safetensors Transformer checkpoints and ran eight CPU workers across development
and final evaluation, with EOS completion, routing, identity, restoration and budget
checks. Those checkpoints establish engineering behavior, not model capability.

The MCP diagnostic test builds a local Transformer, submits a teacher-forced experiment
through the real server and reads nonempty token and activation evidence through the
typed SDK. Public study JSON retrieval is exercised through the server, including
checksum verification and refusal to read a sealed case by ID.

## Real Qwen evidence

[The complete evidence](wave3-qwen/README.md) uses the pinned Qwen3-0.6B checkpoint on
RTX 5090, BF16, with no download or training. Its fingerprint exactly matches the
earlier recorded model identity.

- Zeroing sixteen columns in one MLP down-projection changed **16,384 stored scalars**.
  Full model-state hashes matched after restoration.
- Two supplied continuations changed total log probabilities from approximately
  `[-9.50479, -7.02161]` to `[-9.87694, -6.76319]`. These are measured diagnostic
  changes in opposite directions, not an accuracy improvement.
- Each case recorded 64 selected activation values. Fresh-worker execution and
  portable replay matched the nonempty probability, capture and weight evidence.
- A study ran **16 GPU workers / 32 case executions** across two seeds, original,
  repeated identity, a prompt comparator and the candidate, including its final phase.
  Every worker completed; the final comparisons were fully scored and comparable.
- Development verdict: **no change**. Final scientific verdict: **inconclusive**,
  recommending **retain the original**. The edit did not establish target improvement
  beyond all registered comparisons.
- Strict replay of the legacy wave-2 bundle preserved its exact identity, inspection,
  outputs and stable evidence. Original bundle bytes were unchanged.

The four sampled prompts are public integration fixtures. They do not establish
generalization or a useful repair, and seed repeats are not independent questions.
Study budget usage records reserved ceilings rather than actual GPU time.

## Failures found and resolved

Peer review caught effective EOS-list handling, rounded JSON numbers incorrectly
matching, missing verification of reconstructed SDK evidence, inaccessible large
scoring-constraint records, and publication of NUL-only tensor files. Each received
a targeted fix and regression coverage. Large cases, comparators and assessments now
have complete bounded retrieval; tensor binaries and NUL-containing files are rejected
by the publication guard.

The Qwen harness initially stopped after successful worker execution because the
engine marked a scientifically inconclusive comparison as a lifecycle error. The
engine now distinguishes complete, comparable negative evidence from incomplete or
invalid execution. The original Qwen ledger, error marker and harness failure remain
unchanged. [Recovery evidence](wave3-qwen/RECOVERY.md) explains the exact sequence;
new lifecycle regression tests cover the corrected behavior.

During integration, an old MCP capability expectation still required schema 0.2;
it was updated to the intentionally added 0.3 surface. The Keywork check initially
lacked its required `KEYWORK_REPO` environment variable and passed once pointed at the
existing read-only checkout. Offline uv resolution initially used the wrong cache;
using the repository's existing `.cache/uv` completed without dependency changes.

## Release checks and limits

The [security delta review](../security-wave3.md) covers the expanded trusted-local
surface. It is separate from the earlier 0.2 publication review. Run
`scripts/validate_release.py` to build and inspect wheel/source archives, verify private
canary exclusion, and optionally test a wheel installation outside the source checkout.
Its machine-readable result is saved under the ignored `.cache/release-validation.json`.

The implementation remains local experimental software. No commit, push, public
publication, user configuration change or permanent service registration was made.
Distributed execution, quantized/tied-weight editing, arbitrary-code isolation,
merged checkpoint export, broad benchmark adapters and hosted community features
remain outside this release.
