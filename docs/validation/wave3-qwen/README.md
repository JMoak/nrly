# Wave3 Qwen integration evidence

Generated by [validate_wave3_qwen.py](../../../scripts/validate_wave3_qwen.py)
from the existing pinned Qwen3-0.6B cache. Read `summary.json` for the terminal
acceptance status and `failure.json`, when present, for an unsuccessful attempt.
The script refuses to overwrite a nonempty evidence directory or run store.

This is a real-model GPU execution check on public smoke prompts. It does not
establish capability improvement, statistical generalization, or equivalence to
the WSP-Scope benchmark. No checkpoint download or training is involved.

`native-diagnostics.json` records supplied-continuation probabilities and selected
input activations before, during, and after an edit that zeros the first sixteen
columns of layer zero's MLP down-projection. The complete model-state digest is
checked after restoration. The two continuations are supplied observations, not
generated task answers; their evaluation is unscored.

`diagnostic-run.json`, the diagnostic replay output, and `bundles/` establish
fresh-worker execution and exact nonempty probability/capture/weight evidence
replay. `legacy-wave2-replay.stdout.json` checks the original wave2 bundle without
rewriting it, including its model identity, specification digest, output text,
weight evidence, and inspection captures.

`study-recipe.json` preregisters two sampling seeds, a prompt comparator, one
candidate, and target/regression groups. There are two development prompts and
two different final prompts. `public-smoke-holdout.json` deliberately discloses
the latter; they test the one-shot finalization mechanism and are not a secret
research holdout. The same candidate is used throughout, without a search.

Each phase contains eight isolated workers: baseline, repeated no-op, prompt
comparator, and candidate under each seed. `development/` contains public
paginated development outputs. `public-smoke-runs/` contains the full sixteen
public execution records, including the disclosed final prompts. Final verdicts
and descriptive seed variation appear in `study-final.json`. Seed repeats must
not be counted as additional independent questions.

`study-events.json` retains the study event chain. Budget usage is charged as
admitted ceilings, including the final reservation; it is not measured GPU time
or actual generated-token expenditure. `artifact-inventory.json` records SHA-256
digests of the evidence files present when the script completes.
